# Exchange 可信市场与低流动性价格机制设计

**日期：** 2026-07-31
**目标运行环境：** QuickShop-Hikari 6.2.0.11、Paper/Folia、Java 21
**状态：** 已确认设计，待实现
**范围：** Exchange addon 的可信参考价、低流动性防操纵、管理员热更新 GUI 和 K 线 v2

## 1. 目标与非目标

Minecraft 服务器的交易市场通常只有少量长期参与者、成交间隔不稳定、物品数量离散，不能直接把现实证券市场的连续成交、深度和市值假设搬过来。本设计的目标是：

1. 合法成交仍按订单簿、冻结资产、手续费和账本规则正常完成。
2. 两个不同账户反复对敲不能直接把玩家看到的“市场价格”、价格笼子或熔断基准推到他们想要的位置。
3. 真实成交记录不被修改或伪造；玩家可以同时看到最近真实成交价和稳定的可信参考价。
4. 服务器管理员无需关服即可调整指导价、风险参数、市场状态和展示参数，并获得可审计的预览与结果。
5. 稀疏成交时 K 线不生成虚假的无成交蜡烛，并能清楚表达空窗、单点和平价市场。

不在本设计范围内的内容：

- 不保证真实玩家无法通过大量不同账号影响市场；账号关联和反女巫系统属于服务器治理层。
- 不把市场改造成自动做市商或虚拟无限流动性池。
- 不允许管理员通过普通按钮伪造一笔玩家成交。
- 不改变 QuickShop 6.2.0.11 的 TNML 二进制兼容约束。

## 2. 三层价格模型

每个市场同时维护三种价格：

| 名称 | 来源 | 用途 | 是否写入真实成交历史 |
| --- | --- | --- | --- |
| 最近成交价 `lastTradePrice` | 最近一笔已结算 Trade | 透明展示、原始成交 OHLCV | 是 |
| 可信参考价 `trustedPrice` | 本设计的有界影响状态机 | 玩家主标题价格、价格笼子、市价单滑点、熔断基准 | 否，独立持久化 |
| 管理员指导价 `guidancePrice` | 管理员审计操作或初始 `base-price` | 低参与市场锚点和管理预期 | 否 |

玩家行情摘要默认把 `trustedPrice` 放在主位置，把 `lastTradePrice` 标注为“最近成交”。例如：

```text
市场价 100.50（可信参考）
最近成交 115.00
可信度 低流动性 · 影响受限
```

任何价格都必须经过市场结构规则的 `min-price`、`max-price` 和 `tick-size` 校验。管理员调整指导价不会改写 Trade、原始 Candle 或最近成交价。

## 3. 可信市场领域模型

### 3.1 `TrustedPricePolicy`

`TrustedPricePolicy` 是不可变的市场策略快照。策略版本随每次热更新递增，并随每个影响事件保存。默认值如下；所有比例都是十进制比例，例如 `0.005` 表示 0.5%。

| 参数 | 默认值 | 说明 |
| --- | ---: | --- |
| `budgetWindow` | 6 小时 | 市场、账户和交易对影响额度的滚动窗口 |
| `confidenceWindow` | 24 小时 | 参与度、集中度和活跃时间的统计窗口 |
| `perTradeCap`（低流动性） | 0.005 | 单笔成交最多推动可信价 0.5% |
| `marketBudget`（低流动性） | 0.030 | 市场在预算窗口内最多吸收 3% 的绝对移动 |
| `accountBudget`（低流动性） | 0.015 | 每个参与账户最多吸收 1.5% 的绝对移动 |
| `pairBudget`（低流动性） | 0.0075 | 同一无序买卖双方最多吸收 0.75% 的绝对移动 |
| `anchorBand`（低流动性） | 0.10 | 可信价距指导价最多 10% |
| `reversionPerHour`（低流动性） | 0.005 | 无新成交时每小时向指导价回归最多 0.5% |
| `perTradeCap`（成长中） | 0.015 | 单笔最多 1.5% |
| `marketBudget`（成长中） | 0.080 | 市场最多 8% |
| `accountBudget`（成长中） | 0.040 | 账户最多 4% |
| `pairBudget`（成长中） | 0.020 | 交易对最多 2% |
| `anchorBand`（成长中） | 0.25 | 距指导价最多 25% |
| `reversionPerHour`（成长中） | 0.0015 | 每小时回归最多 0.15% |
| `perTradeCap`（稳定） | 0.030 | 单笔最多 3% |
| `marketBudget`（稳定） | 0.200 | 市场最多 20% |
| `accountBudget`（稳定） | 0.080 | 账户最多 8% |
| `pairBudget`（稳定） | 0.040 | 交易对最多 4% |
| `anchorBand`（稳定） | 0.60 | 距指导价最多 60% |
| `reversionPerHour`（稳定） | 0 | 不做自动回归 |

策略校验要求：所有比例在 `[0, 1]` 内，`pairBudget <= accountBudget <= marketBudget`，`perTradeCap <= marketBudget`，窗口为正，锚定带不超过结构价格边界可表达的范围。策略不得把预算设为无限；管理员若确实需要自由价格发现，应使用稳定等级的有限上限，而不是关闭硬约束。

### 3.2 `TrustedPriceState`

每个市场只有一个由单写入者更新的状态：

- `marketId`；
- `trustedPrice`：保留 `priceScale + 8` 位内部精度，展示时按市场 `price-scale` 舍入；
- `guidancePrice`；
- `lastEvaluatedAt`；
- `confidenceTier`；
- `policyVersion`；
- `lastMatchSequence`；
- `stateVersion`。

状态更新和对应成交必须处在同一个数据库事务中。状态不能只放内存；服务器重启后预算、锚点和可信价必须保持不变。

### 3.3 `TradeInfluence`

每笔已结算 Trade 生成一个不可变的影响事件，包含：

- Trade 的 `tradeId`、`marketId`、`matchSequence`、`buyerAccountId`、`sellerAccountId`、`price`、`quantity` 和 `executedAt`；
- 规范化的无序交易对键 `pairKey`（两个 UUID 按字典序拼接）；
- 事件发生前后的可信价；
- 请求移动比例、实际接受移动比例、数量因子；
- 计算时的可信度等级和策略版本；
- `LIMITED_BY_TRADE`、`LIMITED_BY_MARKET`、`LIMITED_BY_ACCOUNT`、`LIMITED_BY_PAIR`、`LIMITED_BY_ANCHOR` 等原因标记。

影响事件不是拒绝记录，也不是把成交标记为非法。即使实际接受移动为零，真实成交仍会结算并进入原始历史；该事件只说明它没有获得可信行情权重。

## 4. 有界影响算法

所有计算使用内部高精度 `BigDecimal`，最后才按市场精度显示或比较。设：

- `R` 为成交前可信参考价；
- `P` 为真实成交价；
- `G` 为指导价；
- `q` 为成交数量；
- `L = max(1, ceil(discoveryQuantity / 20))` 为单笔完整影响数量。

计算顺序如下：

1. `direction = sign(P - R)`。若 `P == R`，影响为零，但成交仍计入参与统计。
2. `quantityFactor = min(1, q / L)`，除法使用高精度并向下舍入。
3. `requestedMove = min(abs(P - R) / R, tier.perTradeCap) * quantityFactor`。
4. 取当前窗口内尚未过期的事件，得到剩余额度：
   - `marketRemaining = tier.marketBudget - sum(all accepted absolute moves)`；
   - `buyerRemaining = tier.accountBudget - sum(buyer account events)`；
   - `sellerRemaining = tier.accountBudget - sum(seller account events)`；
   - `pairRemaining = tier.pairBudget - sum(pair events)`。
5. 计算指导价锚定边界 `[G * (1 - anchorBand), G * (1 + anchorBand)]`。若目标方向会越过边界，只允许移动到边界；若当前可信价已经在边界外，只允许向边界或指导价方向移动。
6. `acceptedMove` 是 `requestedMove`、四项剩余额度和锚定边界允许移动量的最小值。
7. `R' = R * (1 + direction * acceptedMove)`。事件记录 `R`、`R'` 和所有受限原因；所有额度按 `acceptedMove` 的绝对值消耗。

额度按绝对移动消耗，反向交易不能恢复额度；只有事件离开滚动窗口后才释放额度。这样“先拉高再砸低”与“来回刷价”都不能获得额外可信行情权重。单笔成交因 tick 舍入显示不变时，内部精度仍保存移动；只有实际内部移动为零时才不消耗额度。

成交价格可以继续是真实价格，前提是它通过现有订单风险、价格笼子和资产结算校验。可信影响被限制不等于拒绝合法成交。

## 5. 低流动性等级与参与面

等级只影响未来可信价吸收速度，不决定玩家能否交易。统计使用过去 24 小时的已结算、不同账户成交事件；同一账户或同一交易对的统计贡献有上限，防止单纯刷笔数制造“活跃市场”。

指标定义：

- `participants`：不同买方和卖方账户数量；
- `pairs`：不同无序交易对数量；
- `effectiveTrades`：每个交易对最多计 5 笔、每个账户最多计 10 笔后的成交笔数；
- `activeBuckets`：有成交的 4 小时 UTC 时间桶数量；
- `accountConcentration`：按每笔 `min(quantity, 5L)` 的置信权重计算的最大账户占比；
- `pairConcentration`：同样权重下的最大交易对占比。

等级判定按稳定、成长、低流动性顺序：

```text
稳定：participants >= 8，pairs >= 6，effectiveTrades >= 20，
      activeBuckets >= 4，accountConcentration <= 0.35，
      pairConcentration <= 0.25
成长中：participants >= 4，pairs >= 3，effectiveTrades >= 6，
        activeBuckets >= 2，accountConcentration <= 0.60，
        pairConcentration <= 0.50
其他：低流动性
```

等级降级不会瞬间把可信价跳回指导价；新交易立即使用较严格的额度和锚定边界，无交易时按该等级的 `reversionPerHour` 平滑回归。两个账户无论交易多少笔都只有 2 个参与者和 1 个交易对，因此始终不能达到成长中等级。

等级降级不回滚已经发生的可信价移动。如果旧等级的非过期事件已经超过新等级的某项额度，该项剩余额度视为零，直到旧事件离开窗口；只有之后的新移动才按新等级额度计算。

## 6. 无交易时的锚定回归

市场维护任务每分钟最多执行一次状态评估。对距离上次评估的小时数 `h`，按当前等级执行：

```text
reversion = min(abs(G - R) / R, tier.reversionPerHour * h)
R' = R 向 G 移动 reversion
```

这不是成交，不写入 Trade、OHLCV 或成交量；它只生成一个 `ANCHOR_REVERSION` 的可信状态调整事件、更新可信参考状态和可信参考线。回归后的价格仍按结构边界和 tick 规则约束。若状态更新失败，保留内存旧状态并重试，不能向玩家展示未持久化的新值。

## 7. 两人对敲的确定性结果

默认指导价和可信价均为 `100.00`，市场为低流动性，成交数量 `q >= L`，两个不同账户只组成一个交易对。假设两笔真实成交分别为 `115.00` 和 `85.00`，都通过订单风险校验：

1. 第一笔请求向上移动 15%，受单笔上限限制为 0.5%，可信价变为 `100.50`，交易对消耗 0.5% 额度。
2. 第二笔请求向下移动 15%，交易对只剩 0.25%，可信价变为 `100.24875`，并消耗剩余额度。
3. 后续同一交易对在 6 小时窗口内继续成交，仍可结算，但 `acceptedMove = 0`，不会改变可信价、价格笼子或熔断基准。
4. 玩家看到的主市场价保持约 `100.25`，最近成交价可以显示 `85.00`；两人不能仅靠反复成交把标题价格推到 115 或 85。
5. 即使窗口过期，两个账户仍只有 2 个参与者和 1 个交易对，等级仍为低流动性，可信价距指导价不能超过 10%，并继续受每窗口交易对预算约束。

## 8. 持久化与重启恢复

新增三个持久化对象：

### 8.1 `trusted_market_state`

每个市场一行，主键为 `market_id`，保存 `trusted_price`、`guidance_price`、`last_evaluated_at`、`confidence_tier`、`policy_version`、`last_match_sequence` 和 `state_version`。

### 8.2 `trusted_market_influence`

每笔 Trade 一行，唯一键为 `trade_id`，保存参与方、交易对、价格、数量、事件前后可信价、请求/接受移动、等级、策略版本、原因标记和时间。索引至少覆盖 `(market_id, executed_at)`、`(market_id, buyer_account_id, executed_at)`、`(market_id, seller_account_id, executed_at)` 和 `(market_id, pair_key, executed_at)`。

### 8.3 `trusted_market_adjustment`

可信价不是 Trade 造成的变化各保存一行，唯一标识由 `adjustment_id` 生成，包含 `market_id`、调整类型（`ANCHOR_REVERSION` 或 `ADMIN_REANCHOR`）、前后可信价、前后指导价、操作者（维护任务可为空）、原因、策略版本和时间。该表既保证无交易回归可恢复，也让管理员重设不会伪装成玩家成交。

成交写入顺序为：订单簿和结算变更、Trade、影响事件、可信状态、原始行情 Candle，最后提交同一事务。任何一步失败都回滚整笔成交；不能出现资产已结算但预算未记录的状态。维护回归和管理员重设则在同一写入边界内写入调整事件与可信状态，不能只改内存。

启动恢复：

1. 读取 `trusted_market_state` 和策略版本，并恢复窗口内的 `trusted_market_adjustment`。
2. 只加载预算窗口与置信窗口内的影响事件，按 `matchSequence` 重放并校验状态版本。
3. 若可信状态不存在，使用旧 `market_state.reference_price` 作为初始指导价和可信价；若不存在则使用结构 `base-price`。
4. 旧数据库迁移时从完整 `trades` 表读取买卖双方生成影响事件，不使用只含价格/数量的旧 `MarketTradeSample` 作为唯一恢复来源。
5. 若事件唯一键、序列或状态校验失败，市场进入 `PAUSED` 并写入错误审计记录；不得静默清空预算或回退到可被重置的内存状态。

## 9. 价格、报价和熔断数据流

```text
订单预检
  └─ 读取可信参考价 R（价格笼子、市价滑点、风险校验）
订单撮合与资产结算
  └─ 生成真实 Trade(P, q, buyer, seller)
事务内可信影响计算
  ├─ 保存原始 Trade 和 OHLCV
  ├─ 更新 TrustedPriceState(R -> R')
  └─ 保存 TradeInfluence
读模型
  ├─ MarketQuote.lastPrice = 最近真实成交价 P
  ├─ MarketQuote.referencePrice = trustedPrice R'
  ├─ MarketQuote.confidenceTier = 当前参与面等级
  └─ K 线 = 真实 OHLCV + 可信参考线
```

价格笼子、市价单保护和新的熔断基准使用可信参考价。原始成交偏离、被零权重吸收的成交和重复交易仍进入审计与告警，但不会单独把可信基准推走。市场级熔断以可信价在熔断基线上的移动为主；原始价格超过结构边界仍由现有订单风险直接拒绝。

## 10. 管理员热更新与 GUI

### 10.1 可热更新参数

无需关服、可通过管理员 GUI 修改：

- `guidancePrice`；
- 低流动性/成长中/稳定三档的影响上限、预算、锚定带和回归速度；
- 预算窗口、置信窗口和展示刷新周期；
- 价格笼子、市价滑点、熔断阈值和熔断时长；
- maker/taker 手续费；
- 市场 `OPEN`、`PAUSED` 和受控恢复状态；
- K 线周期、专业布局、成交量和可信参考线显示。

交易物品、结算货币、`price-scale`、`tick-size`、`min-price`/`max-price` 等结构参数属于高风险修改：必须先暂停市场，检查挂单、冻结资产和待处理转账；不满足条件时只显示预览和阻止原因。

### 10.2 指导价操作语义

- **设置指导价**：修改 `guidancePrice`，不改变最近成交价或可信价；后续影响边界和回归目标立即使用新指导价。
- **重设可信参考价**：危险操作，将可信价设置为新指导价，但不创建 Trade、不修改 OHLCV；要求市场暂停、二次确认、原因和完整审计。
- 指导价改变不自动取消挂单；预览必须列出当前挂单中将落在新笼子外的订单，管理员可选择先处理或取消。
- 公开 UI 不提供“伪造最新成交价”按钮。

### 10.3 GUI 流程

```text
管理中心
└─ 市场管理
   ├─ 选择市场
   ├─ 概览（可信价、最近成交、等级、预算余量）
   ├─ 状态控制（暂停、恢复、熔断解除）
   ├─ 价格与数量（指导价、可信价重设、笼子）
   ├─ 风控与熔断
   ├─ 手续费
   ├─ 图表与展示
   ├─ 挂单检查/取消
   └─ 审计记录
```

点击参数后进入聊天输入或选择器，展示旧值、新值、挂单影响和风险等级；管理员填写原因后，对危险操作再次确认。所有 DB 操作在 Exchange 写入执行器异步完成，持久化成功后才原子替换运行时策略。失败时运行时继续使用旧策略，并在 GUI 显示失败原因。

权限按操作分离，至少包括 `market.view`、`market.risk`、`market.price`、`market.structure`、`market.orders` 和 `market.audit`。GUI 是主要入口，命令只作为同一服务的自动化入口，不能绕过预览、权限、确认或审计。

## 11. K 线 v2

### 11.1 数据原则

- 原始 Candle 仍只来自真实成交，包含 `open/high/low/close/volume/notional`。
- 默认聚合周期按 `5m`、`15m`、`1h`、`6h`、`24h` 选择，不为无成交时间生成零成交 Candle。
- 当前未落盘的分钟成交可作为 live Candle 合并一次；不能与已持久化数据重复计量。
- 可信参考线使用影响事件和维护快照；没有可信状态变化的长空窗显示断线或水平段，不绘造交易。

### 11.2 自适应选择

根据周期内有效 Candle 数选择展示密度：

| 地图尺寸 | 目标有效蜡烛数 | 信息层级 |
| --- | ---: | --- |
| `1x1` | 8–12 | 当前可信价、最近成交、涨跌、等级、可信线或单点 |
| `2x1` | 16–24 | 真实 K 线、可信线、成交量、时间轴 |
| `2x2` | 32–48 | 完整 K 线、成交量、价格轴、可信度摘要、空窗标记 |

有效 Candle 不足时扩大柱宽和间距，不强行填满；只有一根 Candle 时显示单区间摘要；所有价格相同时以价格的 1%（最低一个 tick）做视觉留白，并明确“平价”；长空窗使用间隔标记。

### 11.3 视觉语义

- 可信参考线使用独立颜色和图例，不覆盖真实 Candle。
- 最近成交价用次要标签显示；主标签默认是可信参考价。
- 颜色沿用当前中国行情配色：上涨红、下跌绿、平盘灰，但文本同时给出数值，不能只靠颜色。
- `1x1` 不塞入不可读的完整坐标轴；`2x1` 以上才显示价格轴和成交量；`2x2` 显示“无成交”间隔与可信度。
- 非 ASCII 市场名、极端价格和小数精度必须安全降级，不得导致地图渲染异常。

## 12. 兼容性边界

实现必须继续遵守 QSH 6.2.0.11/TNML 旧 API 约束：

- 物品名称只能通过兼容层调用 `customName` 或回退到 `display`，业务页面不得直接调用新版方法。
- 不调用 6.2 不存在的 `PlayerInstancePage.setLockEmptySlots`。
- 玩家实例图标通过兼容的图标表更新，不依赖新版 `addIcon` 覆盖语义。
- 点击路由、空槽/拖拽保护和页面切换状态在旧 TNML 上完成。
- 异步数据准备完成后再在 owner 线程打开或刷新页面；不得用未完成的异步图标更新假设旧 TNML 会自动刷新。

## 13. 验收与测试

### 13.1 领域测试

必须覆盖：

- 相同价格、数量因子、单笔上限、市场/账户/交易对预算；
- 反向交易不恢复预算，事件过期后才恢复；
- 锚定边界、指导价内外、无交易回归和等级降级；
- 两人交替及同向对敲的确定性结果；
- 多参与者达到成长/稳定阈值，单一账户刷量不能升级；
- tick 精度、内部高精度和价格边界；
- 真实成交成功但可信影响为零时，账本和原始 OHLCV 仍完整。

### 13.2 持久化与集成测试

- SQLite 和 MySQL 迁移、唯一键、索引、事务回滚和重启重放；
- 交易、影响事件和可信状态只能一起提交；
- 状态损坏时市场安全暂停，不清空预算；
- 报价、价格笼子、市价保护、熔断和 K 线消费可信价；
- 管理员预览、权限、二次确认、原因、原子热更新和审计；
- Paper/Folia owner 线程、QSH 6.2.0.11 实际 JAR 的 GUI 二进制验证。

### 13.3 发布前不变量

1. `lastTradePrice` 永远来自真实 Trade，管理员操作不能修改它。
2. `trustedPrice` 的每次变化都有 TradeInfluence、ANCHOR_REVERSION 或明确的管理员重设事件。
3. 在某个策略版本下，新增接受移动不会使当前窗口的市场、账户或交易对绝对移动总和超过该版本额度；等级降级时若历史事件已超过新上限，新增移动必须为零直到事件过期。
4. 两个账户不能凭成交次数达到成长中或稳定等级。
5. 数据库提交失败时，旧策略、旧状态和旧 GUI 读模型继续有效。
6. 仅用 QSH 6.2.0.11 存在的 API 即可加载、打开和操作 Exchange 页面。
