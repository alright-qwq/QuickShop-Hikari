# QuickShop Exchange 玩家指南

> 适用版本：QuickShop-Hikari 6.2.0.11 / Exchange addon（Paper / Folia）
> 本文面向玩家，覆盖目标、交易规则、指令与 GUI 用法、风控与博弈点。

---

## 1. 目标

Exchange 是 QuickShop-Hikari 的中央化交易市场附加组件。玩家可以：

- 充值 / 提现物品与货币；
- 提交**限价单**（LIMIT）或**受保护市价单**（MARKET）；
- 查看市场行情、自己的挂单、资产和历史；
- 通过托管、冻结、结算、审计机制安全地参与交易。

市场由管理员配置并开启（`markets.yml` 中的市场 `enabled: true` 才会出现在市场列表）。

---

## 2. 快速开始

1. **确认有权限**：默认所有玩家有 `quickshop.exchange.use`，但必须同时在管理员的 Rollout 白名单内，否则指令会被拒绝。
2. **打开交易界面**：输入 `/qse` 或 `/quickshop exchange`。
3. **领取交易手册**：输入 `/qse book`，拿到一本签名的知识之书；主手右键它即可打开市场界面（离线改名无效，需使用原件）。
4. **充值**：
   - 货币：`/qse deposit money <货币ID> <金额>`，例如 `/qse deposit money default 1000`
   - 物品：`/qse deposit item <市场ID> <数量>`，例如 `/qse deposit item minecraft_diamond 64`
5. **下单**：在市场详情页按聊天输入格式输入，或用指令直接创建订单草稿（见第 4 节）。
6. **查看资产与挂单**：`/qse assets`、`/qse orders`、`/qse history`。

---

## 3. 玩家指令总览

```text
/qse                              # 打开市场列表 GUI
/quickshop exchange               # 同上（全名）
/qse book                         # 领取交易手册（主手右键打开市场）
/qse market <市场ID>              # 直接打开某个市场详情
/qse order limit <buy|sell> <市场ID> <价格> <数量>      # 限价单草稿（GTC）
/qse order market <buy|sell> <市场ID> <数量> <保护价>   # 受保护市价单草稿（IOC）
/qse cancel <订单ID>              # 撤销挂单草稿
/qse deposit money <货币ID> <金额>
/qse deposit item <市场ID> <数量>
/qse withdraw money <货币ID> <金额>
/qse withdraw item <市场ID> <数量>
/qse orders                       # 打开「我的挂单」
/qse assets                       # 打开「我的资产」
/qse history                      # 打开「历史」（成交/转账/账本）
```

**说明**

- `<市场ID>` 是配置中的完整市场键，例如 `minecraft_diamond/default`（必须与 `markets.yml` 中的键完全一致）。
- 订单指令不会直接下单：它创建一张**确认页**，你需要在 GUI 里确认后才提交。
- 每条指令都需要对应权限（默认玩家都拥有，管理员可以收紧）：
  - `quickshop.exchange.use`、`quickshop.exchange.deposit`、`quickshop.exchange.withdraw`
  - `quickshop.exchange.order.limit`、`quickshop.exchange.order.market`、`quickshop.exchange.order.cancel`

## 4. GUI 用法

### 4.1 页面导航

GUI 底部导航包含五个核心页面：

| 页面 | 内容 |
| --- | --- |
| 市场列表 | 所有已开启市场：名称、最新价、24h 涨跌、24h 成交量、最佳买/卖价、市场状态 |
| 市场详情 | 单个市场：下单入口、最佳买/卖价、K 线/折线行情 |
| 我的挂单 | 当前有效订单：价格、数量、方向、状态，可撤销 |
| 我的资产 | 托管中的货币与物品余额 |
| 历史 | 成交记录、转账记录、账本变动 |

### 4.2 市场详情页：聊天下单

进入市场详情页后，聊天输入框会提示两种格式：

```text
限价单：<数量> <价格>          # 例：64 100.00
市价单：<数量> <绝对保护价>     # 例：64 90.00
```

- 限价单是 **GTC**（一直有效，直到成交或撤销）。
- 市价单是 **IOC**（立即成交，未成交部分自动取消）。
- 市价单的第二个值是**绝对价格**（不是百分比），代表你能接受的最差成交价；它会在确认页原样保留，延迟确认不会放宽你的保护。

输入合法后会出现**确认页**：确认时会重新校验身份、白名单与权限，请求只能被领取一次。

### 4.3 交易手册

`/qse book` 领取的手册带有插件的 PDC 签名。**主手右键**打开市场 GUI 第一页；副手和左键无效。包满时不会发放物品（不会丢地上）。

## 5. 交易规则

- **订单簿**：中央限价订单簿，按价格优先、时间优先撮合。
- **成交价**：以先挂出的 Maker 订单价格成交。
- **手续费**：每笔成交收取 Maker / Taker 费率（默认 Maker 0.1%、Taker 0.2%，每个市场可单独配置）。挂单提供流动性通常比吃单便宜。
- **自成交保护**：同一账户不能与自己成交，会被拒绝。
- **幂等**：同一请求 ID 的重复提交不会重复执行；确认页过期或失效后需要重新下单。

---

## 6. 市场状态

| 状态 | 含义 | 能否下单 |
| --- | --- | --- |
| `OPEN` | 正常开放 | 可以 |
| `HALTED` | 因价格波动触发熔断，自动暂停 | 不能，到期自动恢复 |
| `PAUSED` | 管理员暂停 | 不能 |
| `RECOVERING` | 重启/恢复中 | 不能 |
| `CLOSED` | 市场关闭 | 不能 |

熔断是保护机制，不是故障：一级波动默认暂停 120 秒，二级默认暂停 600 秒，到期自动恢复。

---

## 7. 风控与博弈点

这套设计针对 Minecraft 低流动性、少数玩家控制大量资金的环境，玩家需要理解这些规则才能有效博弈。

### 7.1 价格笼子（动态限价）

- 下单价格必须在参考价上下 **±20%** 以内（默认），超出直接拒绝（`PRICE_OUTSIDE_CAGE`）。
- **博弈含义**：不能一次性把价格砸穿/拉爆 20% 以上；想大幅改变价格，必须分多笔、逐步推进。

### 7.2 市价单滑点保护

- 市价单默认最多允许 **5%** 滑点，硬上限 **20%**；保护价超过上限会被拒绝（`SLIPPAGE_TOO_HIGH`）。
- **博弈含义**：吃单时要计算盘口深度；盘口太薄，你的市价单可能只能部分成交或直接被拒。

### 7.3 熔断

- 参考价波动 ±10% → 暂停 120 秒；±20% → 暂停 600 秒。
- **博弈含义**：剧烈行情会"冷静期"，不能趁波动连续收割；熔断期也不能下单，防止情绪化追涨杀跌。

### 7.4 可信价与防操纵预算（核心博弈点）

系统为每个市场维护"可信参考价"，并对成交的价格影响施加滚动预算：

- **单笔影响上限**：单笔成交对可信价的推动不能超过阈值；
- **市场 / 账户 / 交易对预算**：一段窗口内（默认 6 小时）总推动量有上限，随时间逐步回退；
- **行为风险升级**：持续、高集中、同向冲击会逐步升级：`OBSERVE → ALERT → PAIR_COOLDOWN`，最终该交易对进入**短时冷却**，期间暂停成交；
- **重启持久化**：预算和告警状态持久化，重启后不会清零重来。

**博弈含义**

- 真实成交**不会被隐藏或回滚**，但可信价的影响被预算约束；
- 双账户对倒、自我成交式的"洗价"：成交仍然发生，但对可信价的影响受限；持续同向操纵会触发冷却，反而锁死你的流动性；
- 想推动价格，靠**持续真实的双向交易**逐步积累流动性，比一次性对倒更有效、也更安全；
- 反过来，做市商可以放心提供双边报价：异常冲击会被预算和熔断拦住，不会瞬间把市场打穿。

### 7.5 托管与审计

- 充值的物品/货币进入托管，下单冻结资产，成交后结算；
- 转账审查（`REVIEW_REQUIRED`）和定期对账是管理员职责；玩家遇到资金异常应通过管理员渠道反馈，而不是重复操作外部物品（重复操作可能导致无法对账）。

## 8. 行情展示（地图墙与告示牌）

> 需要权限 `quickshop.exchange.admin.display`（默认 OP），本文面向服主/管理员玩家。

### 8.1 地图墙

```text
/qse admin display map create <市场ID> [1x1|2x1|2x2] [kline|line] [1h|6h|24h|7d]
/qse admin display map mode <kline|line>
/qse admin display map period <1h|6h|24h|7d>
/qse admin display map refresh
/qse admin display map remove
```

- 在**同一面墙**上摆好完整矩形的空物品展示框（朝向一致、无缺口），注视其中一格后执行 `map create`。
- 尺寸：`1x1` 紧凑摘要、`2x1` 更多轴细节、`2x2` 完整价格/时间轴与成交量区。
- 周期：`1h` / `6h` / `24h` / `7d`；低成交市场会自动选择更细的自适应周期。
- 颜色：上涨红、下跌绿、平盘灰；K 线/折线模式可随时切换。
- 若提示墙不完整，消息会直接告诉你缺第几列第几行、应在哪个方块坐标放置展示框。

### 8.2 告示牌

```text
/qse admin display sign bind <市场ID>
/qse admin display sign refresh
/qse admin display sign remove
```

告示牌显示：市场名称、当前价格、24h 涨跌、最佳买/卖价（无挂单时显示 `-- / --`）或市场状态。

## 9. 常见提示对照

| 提示 | 含义 | 怎么办 |
| --- | --- | --- |
| `rollout-not-allowed` | 不在白名单 | 联系管理员把你加入 Rollout 白名单 |
| `MARKET_NOT_OPEN` | 市场未开放/暂停/熔断 | 等待恢复，或联系管理员 |
| `PRICE_OUTSIDE_CAGE` | 价格超出参考价 ±20% | 调整到笼子范围内下单 |
| `SLIPPAGE_TOO_HIGH` | 市价保护价超过允许滑点 | 收紧保护价或改为限价单 |
| `HALTED` | 熔断中 | 等待自动恢复（120/600 秒） |
| `display-operation-failed` | 展示操作失败 | 查看服务器日志 `Exchange display ... failed` |
| 墙不完整提示 | 展示框不是完整矩形 | 按提示坐标补齐展示框 |

---

## 10. 注意事项

- 订单 ID、交易记录可在历史页查看；撤单用 `/qse cancel <订单ID>`。
- 完全成交后最佳买卖价显示 `-- / --` 是正常现象。
- 市场价格受风控约束，不等于外部 QuickShop 商店价；两者间可能存在套利空间，请自行评估（双向价格笼子会限制单次冲击幅度）。
- 备份、对账、审查由管理员负责；玩家如遇资产问题，保留记录并走管理员渠道。
